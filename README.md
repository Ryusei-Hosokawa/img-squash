# img-squash

ディレクトリ配下の PNG を可逆（劣化なし）の WebP に置き換えて容量を下げ、
Markdown 内の画像リンクも `.webp` に書き換えるTS製CLIツール。

Notion のエクスポートに混ざるスクリーンショットなど、文字や UI が多い画像を想定している。
そうした画像は、可逆 WebP にすると PNG の約 25% の容量になる（JPEG ではほとんど小さくならない）。

## Requirements

- macOS
- Bun
- `cwebp`（`brew install webp`）
- `trash`（`brew install trash`。`--apply` のときだけ必要）

## Setup

bun install

## Usage

```bash
# ドライラン（ファイルは変更しない。容量の変化だけ表示する）
bun src/main.ts [ディレクトリ]

# 適用
bun src/main.ts [ディレクトリ] --apply

# 特定のディレクトリを対象から外す（複数指定できる）
bun src/main.ts [ディレクトリ] --apply --exclude <外すディレクトリ>
```

ディレクトリを省略すると、**カレントディレクトリ配下**が対象になる。
どのディレクトリが対象かは、実行の最初に `対象: <フルパス>` と表示する。

dotfiles から導入している場合は、`isq` で実行できる。

```bash
isq                      # カレントディレクトリ配下をドライラン
isq --apply              # カレントディレクトリ配下に適用
isq <ディレクトリ>       # 指定したディレクトリをドライラン
isq [ディレクトリ] [--apply] [--verbose] [--level <0〜9>] [--jobs <数>] [--exclude <ディレクトリ>]...
```

| オプション | 説明 |
| --- | --- |
| `--apply` | 実際に変換して適用する。付けないとドライラン |
| `--verbose`, `-v` | 一覧を全件表示する（既定は上位10件） |
| `--level <0〜9>` | 圧縮レベル（既定 7）。大きいほど少し小さくなるが、とても遅くなる |
| `--jobs <数>`, `-j` | 同時に変換する数（既定は CPU 数。最大8） |
| `--exclude <ディレクトリ>` | 対象から外すディレクトリ（複数指定できる） |

### 圧縮レベルについて

PNG 52枚（約5.7 MB）での計測。可逆 WebP は、レベルを上げても画質は変わらず、容量と時間だけが変わる。

| レベル | 変換後の容量 | 時間（1枚ずつ） |
| --- | --- | --- |
| 3 | 1.70 MB | 約3.6 秒 |
| 6 | 1.63 MB | 約3.6 秒 |
| **7（既定）** | **1.60 MB** | **約3.9 秒** |
| 8 | 1.59 MB | 約4.9 秒 |
| 9 | 1.49 MB | 約57 秒 |

レベル9は、レベル7より容量が約7%小さくなるだけで、約15倍遅い。小ささを最優先するときだけ、`--level 9` を使う。

### 待ち時間の表示

端末に直接表示しているときは、変換中に次の2行を表示し、終わると消す。

```
⠹ 変換中  ━━━━━━━━━━╸╌╌╌╌╌╌╌╌╌╌  23/51  経過 4.2 秒
  ログイン/image.png
```

- 1行目：スピナー・進捗バー・枚数・経過時間。2行目：いま処理しているファイル名（長いときは前を `…` で省略する）
- 色は、スピナーがシアン、バーの塗りが緑、空きとファイル名が薄い灰色。`NO_COLOR` を設定すると、色は付かない
- 進捗は標準エラー出力に書く。出力をパイプやファイルに渡すときは出さないので、結果の出力は汚れない

## Output

画像ごとの変換前後の容量と削減率を、削減の大きい順に表示する。

```
対象: /path/to/画面仕様書
モード: ドライラン(ファイルは変更しません)

■ 変換する画像(2/3)
  トップ/スクリーンショット.png  451.7 KB → 134.5 KB  -70.2%
  ログイン/image.png             173.9 KB →  25.8 KB  -85.2%

■ リンクを書き換える md(1 ファイル)
  画面仕様書.md  2 件

■ 残す画像(1/3)
  メニュー図.png  WebP のほうが大きい(6.9 KB → 6.9 KB)

────────────────────────────────────
合計 画像 2 枚  625.6 KB → 160.2 KB  465.3 KB 減(-74.4%)

適用するには --apply を付けて再実行してください
```

- 各一覧は、既定では上位10件まで。`--verbose`（`-v`）で全件表示する。
- パスが長いときは、桁が崩れないよう「容量 → パス」の順で表示する。
- 色は、端末に直接表示しているときだけ付く。`NO_COLOR` を設定するか、パイプやファイルへ出力すると、色は付かない。

## Behavior

1. 指定ディレクトリ配下の `.png` を再帰的に探す（`.git` と `node_modules` は辿らない）
2. `cwebp -lossless -z <レベル>`（既定 7）で、並列に WebP に変換する。透過も保たれる
3. 変換後のほうが小さい場合だけ置き換える。大きくなる場合・同名の `.webp` が既にある場合はそのまま残す
4. md 内の `![](…)` と `[](…)` のうち、変換した PNG を指すリンクの拡張子を `.webp` に書き換える。
   書き換える範囲は、対象が git 管理下ならそのルート全体、そうでなければ対象ディレクトリ内
5. 元の PNG は `trash` でゴミ箱に送る（いつでも戻せる）

## Notes

- 何度実行しても安全。PNG が残っていなければ何もしない。
- 可逆 WebP は元の画素をそのまま保つので、あとから JPEG が欲しくなっても、
  `dwebp in.webp -o out.png` で PNG に戻してから変換すれば、元の PNG から作るのと同じ品質になる。
- 書き換えるのは Markdown のリンク記法だけ。HTML の `<img src>` は書き換えない。
- macOS のファイル名は NFD、md 内のリンク文字列は NFC で保存される。照合は NFC に揃えて行う。
- 読み取り権限のないディレクトリは、黙って飛ばして続ける。飛ばした数は結果の最後に表示する（`--verbose` で一覧）。
